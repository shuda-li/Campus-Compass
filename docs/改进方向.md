# Campus Compass 改进方向

> 最后更新：2026-06-05  
> P0 级已全部修复，本文档记录剩余改进方向（P1 / P2 / 新需求）

---

## 🟡 P1 — 影响稳定性

### P1-5：System Prompt 注入环境信息

**现状**：System prompt 是纯静态文本，模型不知道当前数据库里有多少教室、哪些建筑可选。

**改进**：启动时查询 DB 概览，追加到 system prompt：

```
## 当前环境
- 可用教室：E教学楼 12 间，容量 40~150 人
- 可选建筑：E教学楼
- 设备覆盖：所有教室均有基础设备（投影仪/空调）
```

---

### P1-6：工具返回结果 Token 截断

**现状**：工具返回 `json.dumps(result)` 全量输出。Tavily 搜索返回 10 条长结果时，单次 observation 可能占几千 token。

**改进**：在 `dispatch_tool` 外包一层截断，每条工具结果最多 2000 字符。

---

### P1-7：Post-Tool-Call 自动验证

**现状**：工具执行完不检查结果。`find_classrooms` 返回 0 间时不附加任何建议。

**改进**：关键工具加 post-hook，发现问题时自动在返回结果中附加修正提示：

```
find_classrooms 返回 0 间 → 结果追加 "💡 试试去掉设备筛选或降低容量要求"
generate_activity_plan 返回空 → 自动降级为兜底模板
```

---

### P1-8：工具合并精简

**现状**：11 个工具，LLM 每步都要从 11 个选项中选一个，增加选错概率。

**改进**：合并为 7~8 个：

| 合并前 | 合并后 |
|--------|--------|
| `parse_user_input` + `analyze_and_expand_topic` | `understand_request` |
| `find_classrooms` + `score_classrooms` | `find_best_classroom` |

---

## 🟢 P2 — 锦上添花

### P2-9：Agent Team 多角色协作

**现状**：只有一个 Agent 从头干到尾，上下文越滚越长。

**改进**：拆成 3 个独立 Agent，各有自己的上下文：

| 角色 | 职责 | 工具 |
|------|------|------|
| `venue_scout` | 场地勘探 | find_classrooms, score_classrooms |
| `budget_analyst` | 预算分析 | calculate_budget, search_web |
| `lead` | 总协调 | 上述所有 + send_message |

3 个 Agent 并行工作，完成后 lead 汇总。

---

### P2-10：错误→规则自学习

**现状**：踩过的坑下次还踩，没有记忆。

**改进**：维护 `.memory/known_issues.json`：

```json
{
  "patterns": [
    {"trigger": "E304无投影仪", "action": "讲座类活动不要推荐E304"},
    {"trigger": "find_classrooms空结果", "action": "自动降低容量要求重试"}
  ]
}
```

每次启动注入 system prompt，Agent 自动避坑。

---

### P2-11：Checkpoint 快照恢复

**现状**：Agent 中途崩溃 → 状态全丢 → 从头再来。

**改进**：每 5 轮自动 dump `state` 到 `.checkpoints/`，崩溃后从最近快照恢复。

---

## 🔧 Harness 层扩充

### Harness-1：guard.py 硬护栏

**现状**：只有 `observ.py`（日志），没有硬性拦截。

**改进**：工具分发前增加策略检查：

```python
# 例
if tool == "finalize" and has_pending_todos():
    return blocked("todo 未完成")
if tool == "calculate_budget" and participants == 0:
    return blocked("未确认人数")
```

---

### Harness-2：config.yaml 配置面板

**现状**：所有阈值（MAX_TURNS、TOKEN_BUDGET、BREAKER_THRESHOLD）散落在各文件中。

**改进**：集中到 `agent/harness/config.yaml`，一处修改全局生效。

---

## 🏫 教室功能增强

### Room-1：坐标距离评分

**现状**：位置评分只看楼层，同层教室无区分。

**改进**：利用已有的 `coordinate_x` / `coordinate_y` 计算到正门和电梯的欧几里得距离，替代纯楼层评分。

---

### Room-2：时间冲突检测

**现状**：不检查教室是否已被占用。

**改进**：新增 `bookings` 表，查询时排除已预订时段。

---

## 🆕 新能力

### New-1：Agent 读文件能力

**需求**：Agent 目前没有 `read_file` 工具，无法读取用户提供的文件（活动需求文档、预算表等）。

**方案**：

1. 新增 `read_file` 工具：

```json
{
  "name": "read_file",
  "description": "读取用户上传的文件内容（支持 .txt .md .json .csv）",
  "parameters": {
    "file_path": { "type": "string" }
  }
}
```

2. 安全限制：
   - 只允许读取 `uploads/` 目录下的文件（路径锁）
   - 单次最多返回 3000 字符
   - 禁止读取 `.env`、`.py`、系统文件

3. 前端增加文件拖拽上传区。

---

### New-2：导出方案为 PDF / Word

**需求**：用户拿到 HTML 方案后无法保存。

**方案**：finalize 后提供"下载 PDF"按钮。
