### 一、架构定位问题

#### ❌ P0 — 系统不是 Agent，是流水线

`agent/workflow.py` 是一条硬编码的 9 步线性流水线。LLM 不驱动工具调用、不做决策、不管反馈。模型只是一个"文笔助手"，在 Step 2 被叫一次，输出一段文案，然后流程头也不回地走下去。

- 没有 Thought → Action → Observation → 再 Thought 的循环
- 如果教室查询返回 0 间，流程不回头、不让模型重新决策
- 本质是"带 LLM 文案的规则引擎 + 数据处理流水线"，不是 Agent

#### ❌ P0 — 两套方案生成路径字段不兼容

| | `agent/workflow.py`（命令行） | `web/app.py`（Web 端） |
|---|---|---|
| LLM 调用 | `llm_client.call_llm_for_ideation` | `plan_generator.call_llm_for_plan` |
| 方案字段 | `title` / `timeline` / `resources` / `promotion` | `activity_purpose` / `activity_content` / `activity_materials` |
| `agent/formatter.py` 期望 | ❌ 不匹配 → 活动目的/内容/物资永远为空 | ✅ 匹配 |

**影响**：命令行模式生成的 HTML 策划书缺少活动目的、活动内容和物资清单。

---

### 二、记忆系统问题

#### ❌ P0 — L3 长期记忆完全缺失

- 没有跨会话持久化用户偏好（常用建筑、惯用人数、历史选择）
- 用户每次打开网页，Agent 都不认识她

#### ❌ P0 — 没有 Token 预算管理

- 无 `trim_to_budget()` 函数
- 无任何上下文字数/轮数限制
- 无 L2 摘要压缩逻辑

#### ⚠️ P1 — L1 内存 Session 重启即丢

- `web/app.py` 的 `sessions = {}` 是普通 Python dict
- Flask 重启 → 所有用户对话状态归零

---

### 三、任务规划问题

#### ❌ P0 — 没有 TodoWrite 动态规划能力

- 9 步固定流水线 = 计划硬编码在 `agent/workflow.py` 里
- 模型无法自主拆解复杂任务
- 没有 `state.todos`、没有进度跟踪

#### ⚠️ P1 — `completeness_checker.py` 是死代码

- 199 行完整的渐进式追问模块，从未被任何文件 import 或使用

---

### 四、Harness 层问题

#### ❌ P0 — 可观测性几乎为零

- 日志：`print("[Step N] xxx")` — 松散的 stdout，无结构化 trace
- 失败处理：多处 `except Exception: pass` 直接吞异常
- 无评估打分、无回滚机制

#### ❌ P0 — 安全边界不存在

- 无工具白名单
- 无路径锁/沙箱
- 无并发控制 / rate limiting
- 仅 `.env` API Key 隔离合格

### 五、算法 & 功能问题

#### ⚠️ P1 — Sub-Agent / Agent Team 完全缺失

- 无上下文隔离、无子代理白名单、无 JSONL inbox、无花名册

## 2026-05-07 — P0-01 + P0-02 修复：重构为真正的 Agent Loop

### 修复内容

#### P0-01：系统不是 Agent，是流水线 → ✅ 已修复

**问题**：`agent/workflow.py` 是硬编码 9 步流水线，LLM 只做文案不参与决策。

**方案**：新建 `agent/agent_loop.py`，实现两套运行模式：

| 模式 | 触发条件 | 行为 |
|------|---------|------|
| **Agent 模式** | 有 LLM API Key | LLM 作为决策引擎，通过 OpenAI Function Calling 自主选择工具调用顺序，每轮 Thought → Action → Observation → 再 Thought 闭环 |
| **降级模式** | 无 LLM API Key | 确定性流水线（仍用 `plan_generator` 生成完整方案） |

**架构变化**：
- 新增 `agent/agent_loop.py`（~500 行）：Agent Loop + 8 个工具定义 + AgentState + 降级流水线
- 更新 `main.py`：入口改为 `from agent.agent_loop import run_agent`
- 保留 `agent/workflow.py`：后续可删除（已无引用）

**8 个工具**：
1. `parse_user_input` — 意图解析
2. `analyze_and_expand_topic` — 主题分析扩展
3. `generate_activity_plan` — 方案生成
4. `find_classrooms` — 教室查询
5. `score_classrooms` — 教室评分排序
6. `get_navigation` — 导航指引
7. `calculate_budget` — 预算计算
8. `finalize` — 输出最终 HTML

**关键设计决策**：
- `AgentState` 独立于 messages，工具读写 state，LLM 只看到工具返回的摘要
- 每个工具返回精简 JSON 摘要，避免上下文膨胀
- 如果 LLM 循环结束但未调 finalize，自动用已有数据生成 HTML

#### P0-02：两套方案生成字段不兼容 → ✅ 已修复

**问题**：命令行用 `llm_client.call_llm_for_ideation`（字段：title/timeline/resources），Web 用 `plan_generator.generate_plan`（字段：activity_purpose/content/materials）。

**方案**：降级流水线统一使用 `plan_generator.generate_plan`。现在命令行和 Web 走同一套方案生成逻辑，输出包含完整的活动目的、内容环节、物资清单。

### 测试结果

- ✅ 降级模式：`"50人的技术讲座"` → 输出 5 环节 + 6 物资 + 活动目的（200-300字）
- ⏳ Agent 模式：待配置 API Key 后验证

| `main.py` | 修改入口 |

## 2026-05-07 — P0-03～P0-07 修复：Harness 层全面加固

### 修复内容总览

基于 What_is_agent.md 的 Harness 定义（Harness = `agent_loop` + `registry` + `trim` + `persistence` + `config` + `trace`），一次性补齐所有缺失的 Harness 模块。

#### P0-03：L3 长期记忆缺失 → ✅ 已修复

**新增** `agent/memory/persistence.py`：
- `.memory/index.json` 索引 + `.memory/{id}.json` 单条记忆
- `save_preference()` — 保存用户偏好（建筑/人数/活动类型）
- `load_memory_block()` — 启动时注入 system prompt
- `auto_remember()` — finalize 时自动记录上次使用的建筑、人数、类型
- 新增工具 `save_user_preference` — Agent 可主动保存用户偏好

#### P0-04：无 Token 预算管理 → ✅ 已修复

**新增** `agent/memory/trim.py`：
- `estimate_tokens(messages)` — 按 1 token ≈ 3 chars 近似估算
- `trim_to_budget(messages, budget=8000)` — 系统消息永久保留，旧轮次从头部裁
- 每轮 Agent 循环自动调用 `trim_to_budget()`
- `build_summary()` — 为被裁剪内容生成摘要（预留扩展）

#### P0-05：无 TodoWrite 动态规划 → ✅ 已修复

**修改** `agent/tools/registry.py`：
- 新增 `todowrite` 工具定义（OpenAI Function Calling schema）
- `dispatch_tool("todowrite")` → 写入 `state.todos`，重置 `rounds_since_todo`

**修改** `agent/agent_loop.py`：
- System Prompt 新增「任务规划规则」段落
- Nag 机制：`rounds_since_todo >= 3` 且有待办 → 自动注入提醒消息
- `_render_todo_section()` — 实时渲染待办状态到 nag 消息

#### P0-06：可观测性 → ✅ 已修复

**新增** `agent/harness/observ.py`：
- `Trace` 类：结构化事件记录（llm_call / tool_exec / nag / error）
- 每轮 LLM 调用自动记录 tokens_in / tokens_out / tool_calls
- 每次工具执行自动记录名称 / 成功 / 耗时 ms
- `trace.dump()` → `.traces/{session_id}.json` 持久化
- `trace.report()` → 终端输出执行摘要

#### P0-07：Harness 安全边界 → ✅ 已修复

**新增** `agent/tools/registry.py`：
- `TOOL_DEFINITIONS` — 工具白名单，10 个工具的完整 JSON Schema
- `dispatch_tool()` — 统一调度分发，带完整异常捕获 + traceback
- 所有工具执行通过 registry 路由，非白名单工具返回 error

**新增** `agent/state.py`：
- `@dataclass AgentState`：统一状态管理
- 包含 `todos`, `rounds_since_todo`, `total_tokens_in/out`, `round_count`
- 状态独立于 messages，不污染 LLM 上下文
